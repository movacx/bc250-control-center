# Rootless distribution matrix

Tests the installer, the root helpers, the Game Mode (Decky) plugin and the
release packages on throw-away copies of Arch, Debian, Ubuntu, Fedora and
Mint root filesystems, with the fake identity of the distributions this project
targets (CachyOS, Manjaro, SteamOS, Bazzite, Nobara, Linux Mint). **No root, no
Docker/Podman, no virtual machine and no hardware access**: bubblewrap / user
namespaces, and a fake BC-250 (PCI id, amdgpu `mem_info_*`, TTM, `/proc`).

```
bash scripts/qa/rootless-matrix/setup.sh      # once: ~700 MB of rootfs images in ~/.cache/bc250-qa
bash scripts/qa/rootless-matrix/run-all.sh    # everything
bash scripts/qa/rootless-matrix/run-matrix.sh debian-grub bazzite   # a few kinds
```

| Script | What it covers |
| --- | --- |
| `run-matrix.sh` | `kernel-options-set`, `ttm-apply`, restore, `uninstall-check` per family. GRUB is regenerated by the image's own `grub-mkconfig` (Arch reads `grub.d`; an "old GRUB" variant does not), Fedora by the real `grubby`, Bazzite through a `rpm-ostree kargs` stand-in (`stubs/`), Limine through a stand-in `limine-mkinitcpio`. Boot files must come back byte for byte. |
| `run-e2e.sh` | As a normal user with `sudo`: `install-local.sh`, `install-decky-quick-access.sh`, then Game Mode's `main.py` driving every TTM call against the installed root helpers, and the CLI. Includes the Python 3.10 refusal (Ubuntu 22.04 / Mint 21). |
| `run-packages.sh` | Builds the `.deb`, `.rpm`, `.pkg.tar.zst` and tarball, installs each with `dpkg`/`rpm`/`pacman`, and checks the package manager refuses removal while a GPU memory limit is set. |

Limits: Bazzite and SteamOS are their family's rootfs plus the real
`os-release`; the immutable-image behaviour (read-only `/usr`, a real
rpm-ostree deployment, SteamOS updates) and the Gamescope UI itself still need
the physical machine. `/dev/port` is a constant, so CMOS contents are not
modelled (the CMOS lock and the next-boot RAM maths are exercised with fixed
values).
