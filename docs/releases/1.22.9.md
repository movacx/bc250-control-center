# What's New in 1.22.9

Usage for every mounted disk, a new GPU governor screen, a permanent CPU core unlock that works on Bazzite and SteamOS, and fan control v2 everywhere.

## 1. CPU core unlock that stays on, without flashing the BIOS

Your BC-250's two hidden CPU cores (8 cores / 16 threads instead of 6 / 12) can now stay unlocked after every power-off, with no BIOS flash. In **CPU / SMU › Unlock hidden CPU cores**, choose **Persistence**. A small boot service turns the cores on again each time the board starts.

- **Works on Bazzite and SteamOS.** On SteamOS you can now choose this option.
- **Keeps itself up to date.** If the card says **Update available**, press **Update persistence** to install the current version. If it says **Needs repair**, the service did not start with your system: press **Repair persistence**.
- **Prepare the dependencies again after updating.** The persistence tool is not included in the update. On the **Dashboard**, run **Prepare dependencies** with **CPU Core Unlock** selected before you use Persistence. If you skip this, the Persistence button downloads the tool the first time you press it.
- **Tested on Bazzite, SteamOS and Arch Linux.** It has not been tested on CachyOS yet, but you can use it there too. If you do, please report anything that goes wrong.

## 2. MastaG's graphics stack (Arch / CachyOS)

- **More kernels:** besides the stable kernel, you can now install the **RC** and **BORE** kernels. Each comes with its headers and sits beside the stable one, which stays installed.
- **Everything in one package:** **linux-cachyos-bc250-meta** (about 4.5 GB) installs MastaG's recommended set: the stable kernel, dual audio, bc250-cec, bc250-fixes and his three BC-250 Proton builds. Restart Steam afterwards to see the Proton builds.
- **Dual audio:** **bc250-dual-audio** adds a Dolby Digital 5.1 output beside normal HDMI. After installing it, choose **Dolby Digital 5.1 (AC3 Encoder)** as your output. Control Center's own 5.1 output turns itself off while this package is installed, and its TV control does the same with bc250-cec.
- **Kernel switches:** MastaG's optional switches (CH7218 quirk and VRR, forced DSC, and `cs_relink_at_boot`) are in the boot options. They only appear when your kernel supports them.
- **Guided dependency repair:** when the kernel headers require CachyOS’s patched `pahole`, the graphics-stack row offers **Prepare dependencies**. It builds and installs the reviewed CachyOS package before you retry the kernel. Package dependencies are checked before installation, and every requested package must be present in the plan.
- **GPU governor:** on his kernel, the GPU screen offers his recommended Cyan settings with one button.

## 3. Fans and interface

- Fan control v2 in the web interface (phone and PC), the TUI and the Decky plugin.
- The web fan screen now offers per-channel modes, pump roles, editable curves, mixed sensors, tuning, labels, profiles and control from boot.
- Decky respects channels marked as pumps: group presets leave them alone, and manual pump speeds below 30% are refused. The panel also shows each channel's mode and role, and can resume the fan service.
- The web and TUI Dashboard cooling cards select the fan followed by the service, or a spinning fan, instead of always showing a fixed channel.
- Compatibility rows adapt to translated labels and interface scale. Long status and action labels wrap, and controls move below the description when the window is narrow.
- Better contrast in the dark themes on the CPU / SMU and GPU governor screens.
- Fixed: the CPU screen's selectors no longer look dimmed when they are enabled.
- The CPU session console can be resized by dragging its grip and remembers its height.
- The CPU runtime tiles are easier to read, and **Applied tuning** shows **No changes** when no overclock is confirmed.
- Remote access repairs known startup problems and retries once. Empty or corrupt browser registries no longer prevent the server from starting, and startup output is saved to a log for diagnosis.

## 4. Monitoring

- Fixed: in the desktop web interface, the Performance view menu (such as **Total usage** on the CPU tab) opens from the left edge of its button, so its options are no longer clipped by the panel.

### 4.1 Disk usage for every disk (suggestion R-5c848eb0)

- Disk usage now covers every real mounted disk, not just `/`. USB and eSATA drives are included.
- Each disk has its own row on the Dashboard, in Performance and in the Sensors list, on desktop, web and TUI.
- A drive appears on the next refresh after you connect it and disappears when you unmount it.
- System mounts that are not real disks are left out, such as the read-only images on Bazzite and SteamOS and duplicate mounts of the same drive.

## 5. GPU governor

- Redesigned screen with the same layout at every window size: Operating profile, Frequency range, Cyan kernel compatibility, Governor service and Voltage laboratory, then the Danger zone.
- Each profile card shows the voltage range Cyan really uses, for example **715 – 905 mV**. The values come from your `config.toml`, so changes made in the Voltage laboratory show up here, +2000 MHz points included.
- The live telemetry tiles were removed from this screen. The Dashboard and Performance already show them.
- Fixed: on SteamOS, the kernel's frequency-ceiling message no longer overflows the frequency range header.

## 6. Cyan and installation

- Cyan updated to **v0.4.15**. Updating it from the AUR no longer fails with "Dependency failed" until you restart: the installer and service controls register the GPU device before starting Cyan.
- Cyan's performance-mode script is refreshed when upstream changes it.
- If your `config.toml` could only be read by root, it is made readable again before Cyan is installed (report R-7f9500f0).
- Applying a GPU range asks for your password only once.
- Podman: before building a container, the app checks for subordinate IDs and shows the commands to fix them if they are missing (report R-32e499fb).
- New installations start in the standard style.

## 7. Compatibility and Settings

- HDMI Dolby Digital 5.1 now prepares the missing `pactl` audio client before checking the session audio server (report R-44eb28f4). On Bazzite, if it is staged for the next deployment, the app asks for a restart before changing the AC-3 configuration.
- New **Package manager lock · pacman** row in Additional settings › Compatibility (report R-48d27e43). It shows whether pacman is locked and which program holds the lock, and it can safely release a lock left behind by an interrupted update.
- Settings: the game controller options now come before the theme list, and the extra "Same as the application" card is gone.
- Settings › About credits HelixSR, DirectMesh, the FSR4 fork, OpenLinkHub, Thermalright and the Decky installer.

## Reports addressed from 1.22.6 through 1.22.9

This cumulative list includes fixes released in 1.22.6, 1.22.7 and 1.22.8 that are also included in 1.22.9, together with the new fixes and recovery guidance in 1.22.9.

- **R-576f65ba** (since 1.22.6 / 1.22.9): DirectMesh installation repeatedly failed with Meson's “Missing sections” error in a cached `DirectX-Headers.wrap` file. **What changed:** Cached source files are checked before installation. A damaged copy is removed so the installer downloads fresh source. If the same error occurs during the build, the cache is cleared and the user is asked to retry.
- **R-c310d1a4** (since 1.22.7 / 1.22.9): Applying a GPU range failed because Cyan had no safe-point for 1850 MHz in a hand-written `config.toml` whose curve ended at 1750 MHz. **What changed:** Applying a voltage profile fills in missing packaged safe-points while preserving existing points and custom voltages. Points above 2000 MHz are added commented out. Apply a voltage profile before retrying the frequency range.
- **R-5c848eb0** (since 1.22.9): Only one disk's usage was shown, and an external drive was not checked. **What changed:** Every mounted disk now has its own usage row, external drives included (see 4.1).
- **R-48d27e43, R-1bf75324, R-d8d8dc3d** (since 1.22.7 / 1.22.9): Installing failed with “unable to lock database” after an interrupted pacman update. **What changed:** 1.22.7 added guidance for a stale lock. 1.22.9 adds the **Package manager lock · pacman** row, which shows who holds the lock and can safely release a stale one.
- **R-7f9500f0** (since 1.22.9): Cyan could not be installed because `config.toml` was readable only by root. **What changed:** The file is made readable again before Cyan is installed.
- **R-32e499fb** (since 1.22.9): Container builds failed with Podman because subordinate IDs were missing. **What changed:** The app checks them before building and shows the commands to configure them and migrate Podman's state.
- **R-44eb28f4** (since 1.22.9): Enabling HDMI Dolby Digital 5.1 stopped immediately on Ubuntu with “pactl is required.” **What changed:** The workflow installs the missing audio client, then checks the session audio server before changing the AC-3 configuration. Bazzite users are asked to restart first if the client is in the next deployment.
- **R-84a7093e** (since 1.22.8): HelixSR setup stopped with “unknown option”, then showed **Repair required** right after installing. **What changed:** Only the options that setup version supports are passed, and a release the author re-published is accepted.

If any of these problems still happens to you, please send the report again so we can keep working on it.
