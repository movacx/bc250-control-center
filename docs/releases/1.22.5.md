# What's New in 1.22.5

Changes since 1.22.4. A small fix for something that was missed in 1.22.4.

### DirectMesh

- Fixed the DirectMesh install stopping with `install.sh: line 96: libxshmfence-devel: command not found` on Bazzite and `systemd-libs: command not found` on CachyOS (exit code 127).
- The cause was in upstream's installer: it splits its package list over two lines and runs it with `eval`, so the package manager installs only the first line and the second line runs as a program. It happened whenever at least one build package was missing, which is why it worked on systems that already had them all.
- Control Center now installs those build packages itself, from the list in the installer it has just verified, before running that installer. Upstream's installer is still used unchanged and checked against its SHA-256, and you still confirm the package manager's prompt.
- If your install stopped at that line, update to 1.22.5 and press Install again.

Thanks to the two people who sent reports from the app, which pointed straight at the cause: **R-006daa34** (Bazzite) and **R-a51b4e18** (CachyOS).

## If you are updating from 1.22.3: what 1.22.4 brought

### Fans

- **Fan control rebuilt.** A new engine drives each channel on its own: firmware, fixed speed, curve or mix, with a fan or pump role. It adds hysteresis, a step limit, a start kick, stall detection and a critical-temperature failsafe that stays on until you check it. The root helper drives every configured channel.
- **Fans page redesigned:** a channel table with a PWM meter and inline rename, a curve editor you drag with the mouse, and an Apply / Discard prompt. Saved and built-in profiles, and calibration per channel.
- **The curve follows the VRM regulator temperatures** (`bc250_vrm`). When one regulator fails, its last valid reading is kept for 45 s while the other is still read; Nuvoton is used only once every reading has expired. A CPU tuning run can no longer start in the middle of a reading. Thanks to thefriendlyhedgehog (PR #30).
- The dashboard's fan card reads the pump header (CPU_FAN1) again; it showed 0 RPM when another J4003 header was empty.
- The built-in profile with every fan on firmware works, and the labels from issue #29 are fixed.

### Settings and interface

- **Settings has a new layout:** a sidebar with search and flat rows, in the dark and light themes, with more contrast. Overview and Official repositories open inside About instead of in a separate window. The privacy section is gone (its one useful switch moved to Diagnostics), and so are the internal-engine details.
- **Terminal themes:** pick the look of the built-in terminal (Clay Dark, Clay Light, Midnight, Graphite, Paper, or the application's own colours) in Settings or in the welcome screen.
- **The welcome screen applies theme, accent, density and scale live** to the application behind it. Its terminal wears the theme already chosen.
- The terminal header uses the same icons as the rest of the application, and the sidebar scrolls instead of squeezing its items when the terminal is enlarged.
- Fixed duplicated prompt lines in the built-in terminal after it was resized.

### Additional settings

- **Compatibility and Drivers** list their tools by category, one row each, with the action and a *More* menu. Each row names where it applies, and rows that do not apply to your distribution are not offered.
- **Memory and swap** shows the swap policies as a table and TTM and VRAM as rails; each is applied on its own.
- Every governor, the MastaG graphics stack and DirectMesh have an *Open upstream project* entry.

### Graphics and upscaling

- **DirectMesh** (mesh shaders for DX12 Ultimate games, by lonewolf0622) installs from Compatibility. Upstream's installer is checked against its SHA-256. It builds on the host on Arch, CachyOS, Manjaro and EndeavourOS, and in a Fedora container on Bazzite (experimental). The row shows the Steam launch option with a copy button and a version picker. It is enabled per game, never system-wide.
- **HelixSR 3.3:** every per-game change goes through the release's own bridge, the one HelixSR Desktop uses. Per game you can add DLSS (HelixSR Scaler) or HLX FSR 4, switch between them, update, go back or remove it. HelixSR 2 games are migrated only once the bridge confirms. The archive is checked against its published digest. 2.x keeps working as before.
- HelixSR checks that Wine actually starts (inside Toolbx, for example) and says so when none does.
- The async compute dialog no longer promises a log-out; it takes effect through each game's launch option.

### Hardware and boot

- **GDDR6 temperatures** are read from the kernel's `bc250_memory` hwmon module when it is loaded (`sudo modprobe bc250_memory`). No helper, no password and no SMU access.
- **Kernel options** (TTM, mitigations, SMT, quiet boot) work on Arch with Limine: they are written to `limine.conf` and verified, with a backup kept.
- **The BC-250 kernel's amdgpu switches**, shown where the kernel has them: GPU scheduler policy (`amdgpu.sched_policy=2`), HDMI 2.1 / DSC off (`amdgpu.bc250_hdmi21=0`) and picture recovery after a mode change off (`amdgpu.cs_relink_ms=0`). Each applies at the next boot and can be restored from the same row.
- **MastaG's optional packages** `bc250-fixes`, `bc250-paccache-cleanup` and the UGREEN adapter firmware (`bc250-ch7218-fw`) install and remove from the BC-250 graphics stack row.

### Fixes from reports

- The terminal no longer reads other programs' exit numbers as helper errors (`make` showed as "helper version mismatch", `curl` as "Cyan D-Bus"). The diagnosis is read from the actual text, with new error codes.
- Cancelling is not failing: answering "n" to the package manager or declining a download (for example NVIDIA's DLSS DLL) ends with "Cancelled" and no longer offers to send a report.
- BC-250 hardware actions stop with an explanation on a computer that is not a BC-250.
- Kernel-header failures say what actually happened, on Arch/CachyOS and on Bazzite.
- Oberon reinstalls missing kernel headers on SteamOS/Arch, and on Bazzite it builds for the system's own Fedora release.
- SteamOS: the graphics setup runs inside the application's writable-root window, which turns read-only back on when it ends, failure included.
- SteamOS: installs no longer stop with 80 MB free on `/var`. Package downloads go to a temporary folder outside `/var`, so the check asks for 40 MB instead of 100. When `/var` is still too full, the message names each cache with the command that frees it. *Free /var space* (Additional settings › Compatibility › SteamOS read-only mode) clears pacman's downloads, fwupd's metadata and old logs, and keeps UMR's data.
- Cyan's configuration editor no longer refuses a valid file because a commented key sits next to the active one.
- Bazzite: the self-update names the layered package that blocks it and gives the command to remove it.
- Reports show how the CPU core unlock is kept.
- Fedora 45: the installer recognises the system's CA certificates, and remote access over HTTPS works with Python 3.14.
