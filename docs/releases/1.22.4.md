# What's New in 1.22.4

Changes since 1.22.3.

### Settings and interface

- **Settings** has a new layout: a sidebar with search and flat rows, in the dark and light themes. Overview and Official repositories open inside About instead of in a separate window; the privacy section and the internal-engine details, which showed nothing useful, are gone.
- **Terminal themes**: pick the look of the built-in terminal (Clay Dark, Clay Light, Midnight, Graphite, Paper, or the application's own colours) in Settings or in the welcome screen. The terminal inside the welcome screen wears the theme already chosen.
- The terminal header uses the same icons as the rest of the application, and the sidebar scrolls instead of squeezing its items when the terminal is enlarged.
- Fixed duplicated prompt lines in the built-in terminal after it was resized.
- The dashboard's fan card reads the pump header (CPU_FAN1) again; it showed 0 RPM when another J4003 header was empty.
- The GitHub button on the desktop opens Settings › About › Official repositories.

### Additional settings

- **Compatibility** and **Drivers** list their tools by category, one row each, with the action and a *More* menu. Each row names where it applies, and rows that do not apply to your distribution are not offered.
- **Memory and swap** shows the swap policies as a table and TTM and VRAM as rails; each is applied on its own.
- Every governor and the MastaG graphics stack have an *Open upstream project* entry; so does DirectMesh.

### Hardware

- GDDR6 temperatures are read from the kernel's `bc250_memory` hwmon module when it is loaded (it ships off by default with the BC-250 kernels: `sudo modprobe bc250_memory`). No helper, no password and no SMU access from the application.
- Kernel options (TTM, mitigations, SMT, quiet boot) work on Arch with **Limine**: they are written to `limine.conf` and verified, with a backup kept.
- **Kernel boot options** now include the BC-250 kernel's own amdgpu switches, shown where the kernel has them: GPU scheduler policy (`amdgpu.sched_policy=2`, optional), HDMI 2.1 / DSC negotiation off (`amdgpu.bc250_hdmi21=0`) and picture recovery after a mode change off (`amdgpu.cs_relink_ms=0`). Each applies at the next boot and can be restored from the same row; a switch set outside Control Center is left alone.
- **MastaG's optional packages** `bc250-fixes` and `bc250-paccache-cleanup` can be installed and removed from the Arch / CachyOS BC-250 graphics stack row. Dual audio and HDMI-CEC are already covered by the application's own HDMI audio and TV control. The UGREEN adapter's updater and firmware images (`bc250-ch7218-fw`) can be installed and removed the same way; flashing the adapter itself stays the manual command MastaG's README documents.
- DirectMesh and HelixSR 3.3 are managed from Compatibility; the HelixSR archive is checked against its published digest, and a replaced upstream file stops the install with a clear message.

### Fixes from reports

- Declining a prompt (for example the download of NVIDIA's DLSS DLL) is no longer reported as a failure.
- BC-250 hardware actions stop with an explanation on a computer that has none.
- Kernel-header failures say what actually happened; reports show how the CPU core unlock is kept.
- Several SteamOS, Oberon and HelixSR setup fixes.
