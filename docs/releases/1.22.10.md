# What's New in 1.22.10

A searchable guide to every known error, ordered by how often people hit it. Power and memory sensors that build on Arch, a CPU core-mask picker for boards that are not 0x77, HelixSR 3.4, a classic GPU screen for those who prefer it, and a long list of fixes from your reports.

## 1. A note from the developer

- A new button in the dashboard footer, between **Report a problem** and **Ko-fi**, opens a short note: my own BC-250 stopped working, so support is basic until it is repaired, probably in January 2027. Reports from the app are still read; fixes may take longer.
- The note opens by itself **once**: after the welcome screen and the guided tour on a new installation, or on the first start after updating. After that it only opens from its button.
- If you want to help by testing new versions on your BC-250, the note has a button to open my Discord profile.

## 2. Known errors, inside the app

- **Settings › About › Support › Known errors** is a searchable guide to the errors people have reported, with what you see, why it happens and how to fix it on your distribution. You can search by error code, by a line of the message or by a keyword, and filter by module.
- The list starts with the **most frequent** errors, so the first entries are the ones you are most likely to run into. The order comes from the reports received.
- An error window that matches a known error opens the right guide. The matcher ranks entries by how specific the match is and no longer pulls in generic codes.
- **See the reports you sent (suggestion R-ba54e401):** **Settings › About › Support** lists the reports this computer sent, each with **View** and **Copy ID**, so you can follow them. The same page has **Report a problem** and **View reports** (Diagnostics and Movement history). Diagnostics and History left the sidebar; the dashboard's support button opens this page.
- **About** lists the application's folders. Pressing Enter in a search box no longer closes Settings.
- A missing UMR now shows a full error window with the install command for your distribution.

## 3. CPU

- **Core mask picker (suggestion R-643035c1):** in the CPU danger zone, the old checkbox becomes a list of core masks: **0x77**, **0xB7** and **0x7E**. Boards that report a mask other than 0x77 can now unlock their hidden cores. The temporary unlock first tries without forcing and continues only when the board reads exactly the chosen mask; Persistence passes the same mask to the boot service. When the unlock tool is missing or outdated, a dialog offers **Prepare dependencies**.
- core_unlock_bc250 is pinned at 0.3.0.
- The CPU screen's side panel can be resized by dragging its edge, and it remembers its width.
- The manual CPU scale test downloads a missing `bc250_smu_oc` copy at its reviewed revision before running.

## 4. Sensors and telemetry

- **Board sensors on Arch, CachyOS and Manjaro:** **Additional settings › Compatibility › Board sensors** has cards that build Hexxeh's drivers with DKMS: **bc250-vrm** (power delivery) and **bc250-memory** (GDDR6 temperature, BIOS P3.00 only). Each is pinned to a reviewed revision, checked with SHA-256, credited to its author, and has a **Remove** button. bc250-vrm uses the controller port the fan driver leaves free, so it no longer fails with "failed to request EC port 0x0a20".
- **BC250-Telemetry service** can be installed from the same Board sensors section.
- **Settings › Telemetry** was rebuilt: clearer GDDR6 explanation, the optional daemon at the end, and a step-by-step guide for the I2C bridge right inside Settings. The dashboard's **How to enable** opens that guide.
- **Impossible power readings are no longer shown.** When the regulator returns values a BC-250 cannot produce (for example 797 °C on both rails, 7.97 V input), that rail reads as "no reading" everywhere instead of showing the numbers. In manual mode they are still shown as received, marked in amber, with a note that explains why.
- **GDDR6 says who read it:** a reading from the kernel driver says **Read by the kernel driver (bc250_memory)** instead of BC250-Telemetry, and no longer shows a made-up **MR3 0x00** (the kernel driver gives temperatures only).
- **GDDR6 on boards whose SMU is locked:** after the memory module is patched, a `bc250_memory` driver that stayed silent is woken up so temperatures appear without a reboot. The kernel option `modules-load=bc250_memory` is offered in Settings › Telemetry and Compatibility where the kernel ships it (off by default).
- The dashboard's first reading is about twice as fast. Fields say **Checking…** until the first reading instead of "Not detected", and the power band and CPU card no longer jump while values load.
- The storage group on the dashboard folds behind a small arrow, folded by default.

## 5. GPU

- **Interface style:** **Settings › Appearance › Interface style › GPU screen** lets you choose **Original style** (the layout before the redesign) or **Modern**. The GPU screen also has **Modern design / Classic design** buttons at the bottom to switch on the spot. The classic layout's side panel can be resized too.
- Cyan: the post-install check reads `config.toml` the same way the installer does, so a valid quoted or inline `fix-freq` no longer fails with code 61.
- With `nomodeset`, `amdgpu.modeset=0` or a blacklisted `amdgpu`, the governor start and the hardware video build stop right away and name the option to remove.

## 6. Upscaling (HelixSR)

- **HelixSR 3.4.0 and 3.4.1** are supported, with HelixSR's own frame generation (2x to 6x). 3.4.1 is the new default.
- **Remove games from the list (suggestion R-2e7f6048):** each game in the Upscaling table has a trash button before its name that hides it from the list. A game whose folder is gone reads **Not on disk** with **Remove from list**, and a game Steam uninstalled no longer fails with "no game (.exe) found".
- **HelixSR 3.3.0 installs again.** Its author replaced the 3.3.0 file on GitHub without changing the version, so every 3.3.0 download failed its check. The app now trusts the new file. When GitHub's API does not answer (it limits how often one address can ask), the download is checked against the `SHA256SUMS.txt` the author publishes with the release.
- Settings are applied only when they change, which avoids extra calls to HelixSR's bridge.
- One network build at a time per release folder, and a shader compiler crash is retried once.

## 7. Fans

- **Delete profile** sits next to **Apply profile**, and **Save profile as…** is the first option in **More**.
- A curve that follows **Hottest** now needs a CPU or GPU temperature. If neither answers, the fan goes to its failsafe speed instead of following the cooler board and VRM sensors (reported on 2026-11-16, fans stuck at 31 %).

## 8. Dashboard and interface

- The footer buttons move one at a time, in random order: GitHub hops, Discord wobbles, Telegram's plane flies out and back, the support button sends out a ping, the developer's megaphone sends out sound waves and Ko-fi beats like a heart. **Settings › General › Alert animations** turns them all off.
- The report button is now a **support** button with a headset icon.
- The update badge has its own animation, so a new version is hard to miss.
- The Discord button opens the community's invite link.
- **New installations start in the Standard style, and Settings now shows Standard selected.** Before, Settings showed Formal while the app ran in Standard. **Reset preferences** also returns to Standard.
- Segmented buttons no longer clip their labels, and the reasons shown for blocked actions are translated.

## 9. SteamOS

- **Real Toolkit (rpf16rj)** is the main SteamOS provider. Its tools sit as ordinary rows in System, Kernel and graphics, Video, Audio and TV, and Drivers, each marked with its origin. Rows the app already offers natively are not repeated.
- The read-only root is handled safely: the original state is saved before the toolkit runs and restored afterwards, even after a power cut or a killed terminal.
- keyboardspecialist is updated to v0.40.0; installs from 1.22.9 are still recognized.
- After a factory reset, leftover keyboardspecialist drivers are removed only when they are proven to be its own files.
- The toolkit's FSR4 Proton stays disabled until the toolkit's own RADV is set up, instead of asking for sudo and failing.
- An unsupported SteamOS kernel is rejected before anything is downloaded or sudo is asked.
- Oberon on SteamOS restores missing C and C++ development headers before building.

## 10. Packages and installation

- **pacman lock:** when an action fails because pacman is locked, the terminal now recognizes a lock left over from before the last reboot even while Discover's PackageKit runs in the background, and shows the command to remove it.
- The Arch/CachyOS BC-250 kernel install deletes a package that failed its checksum, refreshes the lists and retries once.
- pacman's "database already registered" (a repository listed twice) is explained with its fix.
- Bazzite and Fedora Atomic: an update that fails names the layered package that cannot be resolved or whose repository key cannot be verified.
- Podman falls back to the `vfs` storage driver when overlay is not supported on Btrfs (hardware video, 32-bit build, cecd).
- GFX1013 source install: only the running kernel's initramfs must rebuild; an old leftover kernel gets a warning instead of failing the install.
- DirectMesh waits for another DirectMesh change that is still running (a second click, or a window left open) instead of failing at once.
- New strings in all 30 languages.
