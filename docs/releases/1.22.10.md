# What's New in 1.22.10

This version adds a searchable guide to every known error, ordered by how often it happens. It also brings power and memory sensors for Arch, a CPU core-mask picker for boards that do not use 0x77, HelixSR 3.4, the return of the previous GPU interface and many fixes based on user reports.

## 1. Known errors inside the app

- **Settings › About › Support › Known errors** is now a searchable guide that gathers the errors users have reported. It explains which symptoms show up, why they happen and how to fix them on your Linux distribution. (It is not perfect yet: beta.)
- You can search by error code, by part of the message or by keywords, and filter by module.
- Errors are ordered by frequency. The first ones are those the most users have run into, according to the reports received.
- When an error window matches a known error, the matching guide opens directly. The matching now favors the most specific entries and avoids showing overly generic codes.
- **See the reports you sent (suggestion R-ba54e401):** **Settings › About › Support** shows a list of the reports sent from your computer. Each one has **View** and **Copy ID** buttons so you can follow it up.
- The same screen also has **Report a problem** and **View reports** (Diagnostics and Movement history). Diagnostics and History were removed from the sidebar; the dashboard's support button now opens this page.
- The **About** section shows the folders the application uses.
- Pressing Enter in a search box no longer closes Settings.
- If UMR is missing, a full error window now appears with the command to install it on your distribution.

## 2. CPU

- **Core mask picker (suggestion R-643035c1):** in the CPU danger zone, the old checkbox was replaced by a list with three masks: **0x77**, **0xB7** and **0x7E**.
- Boards that report a mask other than 0x77 can now unlock their hidden cores too.
- The temporary unlock first tries without forcing the operation, and only continues when the board returns exactly the selected mask.
- The **Persistence** option uses that same mask in the service that runs at boot.
- If the unlock tool is not installed or is outdated, a dialog offers **Prepare dependencies**.
- The core_unlock_bc250 tool is pinned at version 0.3.0.
- The CPU screen's side panel can now be resized by dragging its edge, and it remembers the chosen width.
- The manual CPU scaling test automatically downloads a missing copy of `bc250_smu_oc`, at its previously verified revision, before running.

## 3. Sensors and telemetry

- **Board sensors on Arch, CachyOS and Manjaro:** **Additional settings › Compatibility › Board sensors** gained options to build Hexxeh's drivers with DKMS:
  - **bc250-vrm:** power delivery sensors.
  - **bc250-memory:** GDDR6 memory temperature, BIOS P3.00 only.
- Each driver uses a verified revision, is checked with SHA-256, credits its author and includes a **Remove** button.
- bc250-vrm uses a port of the fan chip that the fan driver does not need. The fan driver's unneeded reservation of that port no longer causes the error "failed to request EC port 0x0a20".
- The **BC250-Telemetry** service can now be installed from the same Board sensors section.
- **Settings › Telemetry** was rebuilt, with a clearer explanation of GDDR6 memory, the optional daemon at the end of the page and a step-by-step guide for the I2C bridge built right into Settings.
- The dashboard's **How to enable** button opens that guide.

### Wrong power readings

- Physically impossible readings are no longer shown. When the regulator returns values a BC-250 cannot produce, such as 797 °C on both power rails or 7.97 V input, **No reading** is shown instead of those numbers.
- In manual mode, the values still appear as received, marked in amber and with an explanation.

### Stuck power sensor fixed

- A first build of bc250-vrm in this version shared registers with the fan driver, which made the readings repeat one value (797 °C everywhere) and eventually stop.
- It now uses its own port.
- If you installed that build, **Repair sensor** rebuilds the driver. Afterwards, unplug the computer for 30 seconds, just once, to reset the fan chip.

### New Repair sensor function

- When bc250-vrm gets stuck repeating one value, the power section of the dashboard detects it and offers **Repair sensor**.
- It restarts the driver and checks whether the readings are real again.
- If they do not recover, it tells you to power the board off and on again.

### GDDR6 improvements

- The component providing the temperature is now identified correctly. If it comes from the kernel driver, **Read by the kernel driver (bc250_memory)** appears instead of BC250-Telemetry.
- A made-up **MR3 0x00** value is no longer shown, because the kernel driver only provides temperatures.
- On boards whose SMU is locked, after the memory module is patched, the `bc250_memory` driver can be activated if it was not answering, so temperatures show without a reboot.
- The kernel option `modules-load=bc250_memory` is offered in Telemetry and Compatibility when the kernel includes that module. It is off by default.

### Other improvements

- The dashboard's first reading now arrives about twice as fast.
- Fields show **Checking…** until the first reading arrives, instead of "Not detected".
- The power section and the CPU card no longer change size while values load.
- The dashboard's storage group can now be folded with a small arrow, and it starts folded by default.

## 4. GPU

- **Interface style:** in **Settings › Appearance › Interface style › GPU screen** you can now choose between:
  - **Original style:** the layout from before the interface redesign.
  - **Modern:** the new design.
- The GPU screen also has **Modern design / Classic design** buttons at the bottom to switch styles immediately.
- The classic layout's side panel can be resized too.
- Cyan: the post-install check now reads `config.toml` the same way the installer does, so a valid `fix-freq` value, quoted or written inline, no longer causes error code 61.
- If the system uses `nomodeset`, `amdgpu.modeset=0` or has `amdgpu` blacklisted, starting the GPU governor and building hardware video acceleration stop immediately, naming the option that must be removed.

## 5. Upscaling (HelixSR)

- Support for **HelixSR 3.4.0 and 3.4.1** was added, including HelixSR's own frame generation, with multipliers from 2x to 6x.
- HelixSR 3.4.1 is now the default version.

### Remove games from the list (suggestion R-2e7f6048)

- Each game in the upscaling table now has a trash button before its name, which hides it from the list.
- If a game's folder no longer exists, **Not on disk** is shown next to a **Remove from list** button.
- When Steam uninstalls a game, the app no longer fails with the message "no game (.exe) found".

### HelixSR fixes

- **HelixSR 3.3.0 installs correctly again.** Its author replaced the 3.3.0 file on GitHub without changing the version number, so every download failed the integrity check.
- The app now accepts the new file.
- If GitHub's API does not answer because of its request limits, the download is verified with the `SHA256SUMS.txt` file the author publishes with the release.
- Settings are only applied when something changes, avoiding unnecessary calls to HelixSR's bridge.
- Only one network build at a time is allowed per version folder.
- If the shader compiler fails, the operation is retried once.

## 6. Fans

- The **Delete profile** button now sits next to **Apply profile**.
- **Save profile as…** is now the first option in the **More** menu.
- A fan curve set to follow the **Hottest** temperature now needs a CPU or GPU temperature.
- If neither of those sensors answers, the fan goes to its failsafe speed instead of following the lower board and VRM temperatures.
- This fixes the problem reported on 2026-11-16, where the fans stayed at 31 %.

## 7. Dashboard and interface

- The footer buttons now have their own animations, which play one at a time in random order:
  - GitHub does little hops.
  - Discord wobbles.
  - Telegram's plane flies out and comes back.
  - The support button sends out a signal.
  - The developer's megaphone sends out sound waves.
  - Ko-fi beats like a heart.
- You can turn all these animations off in **Settings › General › Alert animations**.

## 8. SteamOS

- **Real Toolkit (rpf16rj)** is now the main tool provider for SteamOS.
- Its tools appear as normal rows inside the categories System, Kernel and graphics, Video, Audio and TV, and Drivers.
- Each tool shows where it comes from. Features the app already offers natively are not duplicated.
- The read-only root file system is handled safely: its original state is saved before the toolkit runs and restored afterwards, even after a power cut or a terminal that was forcibly closed.
- keyboardspecialist was updated to version 0.40.0.
- Installations made from version 1.22.9 are still recognized.
- After a factory reset, leftover keyboardspecialist drivers are only removed when they are proven to really belong to that tool.
- The toolkit's FSR4 Proton option stays disabled until the toolkit's own RADV driver has been set up, instead of asking for sudo and then failing.
- An unsupported SteamOS kernel is rejected before any files are downloaded or sudo is requested.
- Oberon on SteamOS restores missing C and C++ development headers before starting the build.

In the end I could not test the whole SteamOS flow because of problems with my BC-250 (it broke and does not turn on). If you send reports I will be watching them, and I hope to get your help; you can contact me on Discord.

## 9. Packages and installation

- **pacman lock:** when an operation fails because pacman is locked, the terminal now recognizes whether the lock was left over from a previous boot, even when Discover's PackageKit runs in the background.
- In that case, it shows the command to remove the lock.
- The BC-250 kernel installation on Arch/CachyOS now deletes packages that fail the integrity check, refreshes the package lists and tries the installation once more.
- pacman's "database already registered" error, caused by a repository configured twice, is now explained together with its fix.
- **Bazzite and Fedora Atomic:** when an update fails, the layered package that cannot be resolved, or whose repository key cannot be verified, is identified.
- **Podman** now falls back to the `vfs` storage driver when overlay is not supported on Btrfs. This applies to hardware video, the 32-bit build and cecd.
- **GFX1013 installation from source code:** only the initramfs of the running kernel must now be rebuilt. If an old leftover kernel exists, a warning is shown instead of cancelling the whole installation.
- **DirectMesh** now waits for another DirectMesh change that is still running, whether from a double click or a window left open, instead of failing immediately.
- New translations were added in all 30 available languages.
